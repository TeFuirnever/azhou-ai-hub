# Measure the user's complete operation

Read this when choosing a performance workload or interpreting an optimization. Name the observable completion point before measuring. Keep local overhead, provider latency, transport, rendering, input response and retained memory separate.

Vary the dimensions that change cost: bytes, records, deltas, turns, children and rendered nodes are not interchangeable. Cover ordinary and tail use with fixed synthetic inputs. Inspect private history only with authorization; extract aggregate characteristics, never prompts, paths, identities or recognizable snippets into a public fixture.

Record the production entry and build, input dimensions, cold/warm setup, timing boundaries, excluded work, runtime/platform and correctness checks. Measure retained memory with intended results still reachable and distinguish transient peak pressure. A parse-and-discard baseline is not equivalent to a validated retained result.

Establish the baseline before changing one causal factor. Measure both the affected component and its user-visible parent. A real input event and resulting UI update prove responsiveness; a fake DOM or timer heartbeat does not. Include late stalls and first activation of deferred work. Use existing runner calibration, repeated samples and a negative control; do not import another project's thresholds or widen budgets around a regression.

Preserve required validation, history, ordering, cancellation, durability and writable readiness. Reject an apparent win that disappears end to end or replaces latency with unbounded retention. Report all relevant samples, workload, limiter, exclusions and measured versus historical claims through the parent benchmark checklist.
