### Worktree and simulator cleanup

1. Snapshot and audit. Record the current worktree list, each branch and merge base, status including untracked files, ignored files, and Treehouse lease owner. Use the real git worktree list, not guessed filesystem paths. A report bucket is advisory; it is never deletion authorization. If a transcript scan is desired, obtain authorization for that private source and only run a bounded, observable read.
2. Preserve active work. Check current users, pinned chats, live jobs, lease holders, installation source references and dependency branches before marking anything eligible. A Git-clean worktree may still be owned by an active lease, native installation or recovery receipt. When evidence is missing, hold the candidate.
3. Verify ownership before deletion. Cross-check real Git paths, head SHA and branch ancestry, and explicitly enumerate tracked, untracked AND ignored files (including new source files and build artifacts). Present their precise paths or a privacy-preserving inventory, why the worktree is thought disposable, and a recovery path. Private transcripts are not inspected by default.
4. Pause on irreversible loss. The audit's scratch:N count denotes untracked files of UNKNOWN ownership; never interpret scratch as disposable. wip:N denotes tracked uncommitted changes. Either status blocks deletion until each file has an explicit disposition from its owner (preserve via commit, archive, verified backup, or individually approved discard). No blanket approval from a merged PR or a safe bucket covers new user files. Unclear ownership, active leases and installation dependencies are blockers, even on merged branches.
5. Remove only after explicit approval and recovery proof. Confirm the particular worktree and its untracked/ignored contents are authorized for removal, no active Treehouse lease remains, and a restored copy or documented preservation decision exists. Prefer non-force git worktree remove for eligible clean trees. Never run git worktree remove --force, git clean, or recursive directory deletion based only on audit classification. If a tool requires force because contents remain, stop, show those exact files, and obtain a new targeted authorization first. Branch and recovery objects must be verified before pruning. Record bytes reclaimed and held worktrees.
6. Simulators and other reclaimers require separate authorization. Treat simulator deletes, runtime removes, DerivedData, snapshots, package caches and ignored build directories as user state. Inventory first, preserve owner-dependent content and avoid treating naming or age as permission. Never erase or relocate these as a side effect of worktree cleanup without an explicit scoped decision.

This playbook can destroy user files; explicit per-target approval, retained evidence and recoverability are release gates. A tool classification or green CI is never permission to discard untracked files.

Reply with the current worktree and lease inventory, each proposed path and approved disposition, recovery proof and actual reclaimed space. Mark blocked items with the exact owner/evidence gap; do not say they were cleaned.
