# 阿舟双端启动呈现方案

## 推荐与取舍

Codex 使用原生窗口拥有整段启动呈现。DSH 使用已核实的宿主早期 HTML 入口拥有首屏遮罩，再由客户端接管。两端共享动画内容、设置语义和交接条件，不共享桌面窗口实现。

推荐保留宿主 IndexedDB 为唯一设置权威。冷启立即显示阿舟自有的静态启动底板，在后台启动宿主；读到本次有效设置后，在同一原生窗口中播放现有动画，最后显露工作区。底板只复用现有已批准的品牌素材，不新增声音、角色、动画或视觉效果。

这保证目标是“阿舟先出现，工作区不抢先露出”。它不保证“点击后立即开始用户自定义动画”。源码没有常驻设置同步服务，因此无法在宿主页还没启动时证明缓存是最新设置。此处修正了先前建议中过于宽泛的立即播放承诺。

如果产品坚持个性化动画也必须在宿主启动前播放，必须另立设置存储与持续同步迁移方案，或者明确接受旧设置。当前推荐不引入常驻服务、不使用旧镜像冒充当前设置。不要让开发模型隐式作出这项产品变更。

## Codex 的用户流程

1. 已运行的宿主沿用核验后激活路径，不显示启动底板、不重播。
2. 冷启通过身份和单实例准入后，原生窗口先完成可见呈现，再启动宿主。
3. 当前可信页面提供已保存设置、宿主语言及外观快照。底板期间可跳过或关闭。
4. 原生 WKWebView 以该不可变快照运行原 animation.js。宿主页仅安装设置与壁纸能力，不再启动第二个自动播放器。
5. 动画自然结束且当前工作区可交接时，撤除原生呈现，显露并按焦点策略激活宿主。
6. 若工作区稍晚就绪，只保留结束画面或底板，使用原有绝对总期限。不得循环、重新计时或把等待算成动画时长。
7. 跳过立即结束自有遮挡。宿主尚未就绪时允许暴露其正常加载过程，结果记为已跳过但工作区未证实；不把用户困在遮罩后。

冷启首帧、窗口位置、多显示器、Spaces、用户切换到别的应用时的行为必须实测。高窗口层级与 activates=false 都不能证明无露底。不要隐藏其他应用、强占所有 Spaces 或反复抢焦点。若无法可靠覆盖目标窗口，该候选不可按无闪现验收。

## DSH 的用户流程

在实际宿主已证明支持的早期 hook 中，加入自有启动标记、关键样式和底板。独立 watchdog 先就绪，才允许开启遮挡。客户端稍后接管同一个启动实例，读取原 DSH 设置，播放现有动画并准备壁纸。客户端第一次可见帧提交后，早期底板才撤除。两个呈现之间不能出现空帧。

客户端失败、插件停用、CSP 拒绝或超时必须释放自有遮挡。若内联脚本被拒绝，样式不能单独永久隐藏宿主。卸载只清理自己增加且仍归自己所有的标记与节点。

当前包只有 no-op host apply 和 DOM-ready client。外部 dsh-startup-secret 的 webServer.tapIndex 是机制参考，不是当前安装支持证据。先查实际版本的 hook、CSP、desktop载体和生命周期，再实施。若不可用，DSH 记为首帧能力缺口；不得用插件加载后覆盖冒充完成同步适配，也不得未经授权修改官方宿主。

DSH 热重载不重播。正常路由变化不重播。一次文档启动最多一次自动播放，显式手动预览另行处理。刷新、新窗口与完整应用重启的策略必须按原包和现有宿主语义核对，不能因共享代码就移植 Codex 的进程启动判据。

## 设置与资源所有权

Codex 仍使用 azhou-codex-startup，DSH 仍使用 azhou-dsh-startup。保存、取消、恢复默认、预览、图片校验保留当前行为。原生只消费本次只读快照，不回写数据库，不持久保存第二份偏好。

快照来自当前已绑定页面的一次已提交记录读取。包含验证后的设置以及按现有规则解析的语言和外观。不存在记录和读取失败必须分开处理。记录确实不存在时才能采用明确默认。动画关闭时不播放，释放底板并继续正常宿主加载，不因为壁纸尚未完成而强制等待。

快照使用一次性身份与内容摘要，不假设当前数据库已有 revision 字段。原生播放期间固定这份输入。后续保存用于下次启动，不能在半段动画中换图或重播；当前壁纸仍可按宿主现有保存语义更新，并报告它自己的版本。

合法记录可达现有 20 MiB 上限，而单次 CDP 有更小响应上限。使用只读、绑定当前页面与请求实例的分块传输，检查总字节、块序、长度、摘要、schema和解码边界。每个响应连编码与外层消息一起低于原 transport cap。保留既有各项限额，不简单抬高全局上限。传输失败释放缓存和句柄，日志仅留固定类别与摘要。

## 最小模块调整

| 当前所有者 | 设计改动 |
| --- | --- |
| Native/CodexSkinDriver.swift | 冷启分支组织自有呈现与后台宿主准备，保留热启、锁和身份验证。优先扩展现有 driver，不新建通用启动框架。 |
| Native/App.swift 的 PlayerStage 与 presentation | 复用窗口和 WKWebView，增加正式冷启的只读快照输入与完成回执。preview 与正式run保持不同用途。 |
| Native/Wallpaper.swift 的 StartupConnector | 保留进程、端口、页面退休和签名边界，加入设置快照读取及独立工作区观察。页面换代只更新工作区证据，不驱动原生动画重播。 |
| Native/SkinHostContract.swift、journal与结果消费者 | 明确原生播放结果与宿主工作区结果。旧 page ready/skipped 不能冒充原生完成。一次迁移全部相关 switch、回执和测试消费者。 |
| image-settings.js | 复用既有校验与默认解析，提供只读有效快照。原生环境消费快照，不能模拟一个可写的宿主数据库。 |
| extension/bootstrap.mjs、renderer.mjs、adapters | 由可信安装参数明确自动播放所有者。Codex正式路径启用工作区能力但抑制page自动播放。手动预览仍可播放。 |
| DSH canonical host/client inputs与build-dsh-plugin.py | 增加被证明支持的早期入口和接管协议，由构建器生成，不直接编辑安装产物。 |
| 文档与验证 | 更新双语入口、包文档、测试契约和真实支持范围，记录安装来源与实机证据。 |

不把 Codex URL、CDP objectId、DSH slots 或 NSWindow 暴露给中性动画核心。两端共享行为契约和适用的纯数据逻辑，宿主接入保持独立。

## 方案比较与综合选择

采用候选 A 的现有 driver 组织方式、终态清理和立即释放的跳过语义。吸收候选 B 的原生结果与工作区结果分离、只读快照和独立工作区观察。B 中额外 launchCoordinator 外观接口不采用，避免重复现有 driver。

候选 C 在设置到达前就开始动画，却同时宣称保留最新设置，无法满足已知数据依赖，予以否决。持久原生设置权威是另一种完整架构，但需要迁移、持续保存通道、确认回执、profile隔离和回退协议，本次不选。静态等待后仍在宿主页播放的方案也不选，它继续受页面生命周期控制。

按 Experience First，把首次可见内容与交接顺序列为验收目标。按 Model the Domain，把播放和工作区建模为两个独立状态。按 Prove It Works，把首帧与设置一致性留作真实产物验证，不用源码阅读代替验收。
