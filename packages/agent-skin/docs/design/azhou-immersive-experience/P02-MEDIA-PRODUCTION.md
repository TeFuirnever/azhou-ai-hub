## 制作路线

1. 先锁Azhou角色形象：以已批准working.png作大头短肢、狐耳、白尾尖、橙发及白橙服装基准。生成正/侧/背与动作参考只作制作输入，不作为最终动画交付。
2. 制作真实角色动作片段和连续多角度镜头。角色动作、发丝/服装/尾部及摄影运动需保持时间一致。不得用转动一张平面图伪装绕行。
3. 用可编辑合成工程制作光效、数据带、玻璃工作面和屏幕矩形轨迹。生成视频不承担准确UI文字；UI布局与最终handoff在可控合成层完成。
4. 与原创/获准音轨同步。先聆听并建立参考cue表，再制作或取得有授权的Azhou音效；不默认静音，也不直接抽原音轨。
5. 输出完整约14秒质量对齐候选，再校准hold/transition与几何。旧12秒只作回归基线；不在素材批准前改生产duration协议。
6. 从同一美术空间制作Dream主题背景及皮肤参数，覆盖侧栏、主页面、Dot、卡片、输入和工作面。不是用视频里的假UI代替真实页面。
7. 媒体批准后按P10稳定能力契约接入P03/P04/P05。真实host ready与影片时钟独立；失配安全释放，不改宿主源码。

## 必交资产

- 完整启动动态资产，先按1080p/24fps对照。容器不预设为MP4；MP4/WebM、带透明表达能力的WebP/APNG/GIF候选或序列帧按同一画面、时间和宿主契约评估。音轨独立获准并保持静音下信息完整。
- 可编辑合成工程、源素材及逐项来源/许可/摘要；不交只有扁平成片而不可维护的链。
- 与成片一致的静态首帧、reduce/失败图、主题背景、主题配置与安全导入包。
- 角色动作片段、音频分轨与cue表、hold/transition配置和坐标校准证据。
- 参考组合/当前基线/候选三方完整录屏及真实操作证据。

## 质量否决

角色走形、多角度身份变化、耳尾/服装闪变、多肢/融合、静态贴图假动作、缺原要求镜头、只给动画不交全窗主题、无授权媒体、假ready、交接露底/跳变、声音取消后不停，任一项均不通过。编码检查、CSS测试绿灯和静态分镜不替代完整片观看与实际宿主操作。

macOS主实现是窗口匹配/fill/12pt圆角/淡出，独立版是fit与无监听器；Windows用DWM实时嵌入且会调整窗口。平台差异明确记录，不能给macOS承诺不存在的DWM能力，也不沿用移动宿主窗口来满足构图。

## 当前能力与下一步

Runway、fal是可选但尚未连接的视频制作服务。现有图像生成与本地合成/编码工具可先做制作输入和技术试样，不把服务连接列为唯一前置。接入任何生成服务前核实账户、费用、输入授权及输出许可。两条制作路线都先做高风险短镜头，再扩成完整动态候选；动态制作候选失败时更换制作路线，不把静态位移交作参考级动画。此质量规则不禁止运行时静态降级；无视频基础模式必须可用，见[可选媒体与全线验证合同](OPTIONAL-MEDIA-AND-VALIDATION.md)。

参考媒体未上传到第三方；只允许用自己的Azhou素材及自写运动描述生成。用户未批准的收费、订阅、外部素材分享不执行。连接等待不阻止角色设定和合成接口准备，但不得在此期间再次把静态原型称为目标交付。

## 最新形式约束

用户询问GIF是否可用。交付目标是参考级连续动作和完整体验，不是指定视频容器或生成插件。Runway只是可选制作工具，未连接不阻止其他路线。GIF不承载音轨，需独立音频；GIF的有限调色板、透明边缘与帧时长粒度需用实际金色光晕、渐变和毛发边缘检查，不能凭扩展名判定好坏。WebP/APNG与视频也需逐宿主实测，不能宣称原生透明或解码支持已通过。

本地已确认ffmpeg、ffprobe、node、swift可用。未在PATH发现Blender，不等于机器所有位置都没有。现有renderer背景入口只接受PNG/JPEG/WebP data URL，不能把GIF/MP4塞入该入口便称支持。下一步只做独立编码/解码样本，不能为媒体修改现有wallpaper传输白名单。

制作按两条可互换路径推进。优先用已批准Azhou图生成正侧背关键姿态，并以可编辑分层/骨骼/序列帧制作真实转向、衣尾动作和场景合成；仅插值静态图不算真实多角度。若角色结构无法稳定，采用可选图生视频获得角色动作层，然后用可控工程合成UI。两条均先审最难2–4秒段，不让工具选择决定质量下限。现有工具能合成和编码，不代表已经有合格角色动作或可动画3D模型。
