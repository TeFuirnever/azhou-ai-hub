# 无视频基础模式与全线验证合同

状态：新增用户要求的设计与执行合同，尚未证明全部实施或验收。本页补充既有阶段，不改写历史回执，也不将已有实现追称为 TDD。

## 基础模式先完整可用

视频是可选增强，不是构建、安装、启动、设置、主题或 Dot 壁纸的必需输入。基础包只依赖已授权的 Azhou 静态与现有素材。没有视频、用户关闭动态或媒体能力不足时，核心操作仍可用，不等待装饰资源或影片结束。

当前源码使用 Canvas 和图片，尚无视频播放器。当前背景入口接受 PNG、JPEG、WebP，不能把 MP4 或 GIF 加进原图片白名单便声称支持。已有图像失败、超时、取消和减少动态测试不证明未来视频失败路径已通过。基础模式的全页面、真实宿主功能仍须逐项验证。

参考级完整动态增强仍须交付连续角色动作、原空间关系、主题与交接体验。运行时静态降级是可靠性要求，不是降低动态制作质量，也不作为“全面动态对齐”的通过证据。

## P02a 与 P02b 的依赖边界

- P02a 冻结与最终影片无关的媒体可选性、资源所有权、取消、错误、减少动态和稳定宿主能力合同。P10 防腐层、基础主题与无视频运行可按对应冻结合同独立开发。
- P02b 冻结最终角色素材、影片时间轴、音轨、构图和视觉质量。依赖最终媒体的 P04 交接、P09 音频及完整动态验收仍等 P02b，不以占位素材通过这些门禁。
- P07、P08 只在各自前置接口已冻结且依赖代码已合入或明确堆叠时实施。此拆分不允许绕过共享文件 owner、UI 审阅、发布权限或真实宿主门禁。
- P06 分别报告基础模式和增强模式。增强未完成不隐去基础模式结果；基础通过不暗示完整参考体验完成。

## 可选媒体的稳定合同

媒体状态与宿主状态分开：未配置、用户禁用、不支持、加载中、可播放、失败、已释放。宿主可操作性只由宿主契约证明，媒体完成或计时器都不能生成宿主 ready。

1. 基础路径不发起缺失视频的请求。增强入口在能力与配置有效时才加载，资源有固定 owner 和 runId。
2. 缺失、404、损坏、格式不支持、拒播、加载超时或播放中失败只停用本实例增强媒体，呈现可用 Azhou 静态或已有素材。错误原因可诊断，不污染已保存设置，不重启宿主，不无限重试。
3. 媒体与音频分别持有资源。关闭、跳过、取消、隐藏、换页、卸载和失败都停止自身声音，释放解码、事件、计时器与对象 URL。清理幂等，单项失败不阻其他释放，旧回调不能复活或清理新实例。
4. 减少动态从首帧禁止视频与循环动态，提供即时完整静态信息。运行中开启则立即停用自身动态，不空等原时长。关闭偏好不擅自重播，按显式重播入口处理。
5. 静态素材也失败时安全退出自有覆盖层并保留原生 UI 操作。未知宿主结构只禁用受影响能力，不猜选择器、扩 CSP、改 DSH 源码或接管共享载荷。

## 全线 TDD 与重构规则

从本合同之后的新行为和修复开始，按公开边界做垂直切片：先运行能因目标行为缺失而失败的测试，再做最小实现，再运行同一测试及相关回归。独立 oracle 来自明确契约或人工核对示例，不调用生产算法生成期望值。记录 red、green 的源身份、命令和原因；基础环境失败不算有效 red。

已有行为先做特征与回归测试，不伪造历史 red。若本来通过，记录已有能力并改选真实缺口。UT、功能、浏览器集成与真实宿主 E2E 是不同证据层级；合成结果不升级为安装或实际使用结论。

重构放在独立审查阶段，先保持行为测试绿灯，再缩减重复状态或迁移调用方。新行为与重构分开绑定差异；不为指标噪声增加高成本架构。涉及生命周期、防腐层、Native 桥和版本迁移时增加独立风险审查。

执行使用实际可用 poteto-mode 与 Codex 适配指引，按复杂度分配 owner、审查和测试，不宣称不存在的模型或云环境。常规文档和机械检查用有限上下文；跨宿主状态、并发资源与争议结论使用完整证据和独立审查。模型、推理预算、并行度按当前工具与角色表确认，质量与可复现证据优先。pstack 仅为工作流参考，不修改其本体。

## 存量代码的覆盖风险账

P10b 与 P07 已有 UT、回归和独立审查记录，但缺少逐切片先 red 后 green 的完整时序证据。因此历史 TDD **未证明**，不等于历史代码“没测试”。历史通过只对应当时冻结的源、评估器和运行输入；后续修改须按影响重新验证，不能沿用旧绿灯证明新版本。

本表是待解除风险，不是补写历史执行顺序。owner 为阶段职责，具体执行者及私有回执留在任务交接记录，不入库。

| P07 渲染测量与门禁变更 | P07 owner、测量审查者 | 旧 strict 0 和 max 1 门禁的失败保留；新条件化协议是不同评估，不能算旧门禁通过 | 冻结适用环境、训练包络和检测目标，运行全新 holdout 与缺陷注入，分别报告结构断言和像素检测力；未证明检测力则继续未通过 |

后续顺序固定为：存量行为特征测试 → 找到真实行为缺口 → 运行能因该缺口失败的测试 → 最小实现并复跑 green 与影响回归 → 独立重构审查。没有真实缺口时记录已有行为，不故意破坏产品制造 red。重构前后保持同一公开行为 oracle，并重新绑定改变后的源与结果。文档检查通过仅说明风险账完整，不解除上述产品风险。

## 冻结与发布门槛

每次验证冻结 HEAD、索引、完整源字节与模式、评估器、素材、运行时及输入。漂移使对应结果失效。测试结果、已知失败及未运行项保留，不覆盖旧证据目录。

运行临时目录与持久任务证据分离。运行结束或交接前，将协议、原始产物、日志、源身份和 manifest 封存到所有 worktree 与 common Git 目录之外的私有持久目录，并校验文件摘要及可读性。临时目录、聊天摘要和单个通过标记都不是持久证据。

恢复工作时先核对封存文件是否实际存在、可读且身份一致。缺少原始数据的历史结果标为“不可复核”，不能靠摘要重建原数据、修改原回执或复用旧通过结论；必要时在新目录以新冻结输入重新验证。部分历史临时证据已经丢失，不能声称全部旧证据仍可用。持久原始证据保持私有，公开设计仅记录方法、状态与经审阅的必要结论，不收录本机路径或原始回执。

性能预算先按基础和增强场景分别注册，缺基线不称达标。几何与结构严格断言，渲染噪声协议只能在已声明条件下使用；独立 holdout 与真实缺陷注入证明检测力，不把新协议通过包装成旧 strict 0 通过。

发布前仍须全仓验证、适用语言覆盖率、正式生成载荷、Native 桥、浏览器功能、真实宿主 E2E、回归及独立审查。缺环境、隔离、用户视觉批准或发布权限时标明具体阻塞，不以基础可用为由跳过门禁。
