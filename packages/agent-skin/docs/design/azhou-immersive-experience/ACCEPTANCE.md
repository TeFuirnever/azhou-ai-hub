## 性能协议

性能阈值是拟定门禁，不是已测结果。先固定设备、宿主版本、显示器、已保存设置和冷启动方法，再记录 trunk 基线。候选和 trunk 交错各至少五次。记录原始样本、p50、最坏值、采样方法及时间戳来源。故障样本不得从成功率中删掉。

不得以宿主加载时间替代播放器时长。12 秒动画语义不变，所有交接仍受 60 秒总期限约束。初始性能提案要求可比较路径的 p50 交互就绪时间不超过 trunk 1.10 倍，峰值 RSS 不超过 trunk 1.20 倍。新增首帧门禁提案为准入后 500 ms 内有自有可见帧。若工作量不同，分别报告新增阶段耗时与端到端时间，不算无意义倍率。

这些提案必须在 NH-10 冻结前根据真实基线评审。缺少基线时状态为 inconclusive，不能编造数字通过。低刷新率、录屏开销及系统忙碌必须随证据披露。首页和任务页静置时不得持续重绘整屏。动画结束后记录 60 秒静置 CPU 与资源释放。

## 真实证据门禁

产品 PR 运行 `python3 scripts/verify.py`，并按 [testing.md](../../testing.md) 运行所改运行时的专项测试与覆盖率门禁。Pet 运行时改变时另跑 Pillow 相关两套工具测试。仅文档检查通过记作 document_checked。

UI 改动需截图和 30 至 60 秒视频交给操作者审阅后合并。测试使用授权且不含敏感内容的工作区。不能重启活跃宿主来迁就测试。安装遵守 [local-install-sop.md](../../local-install-sop.md)，先证明来源与所有权，安装和运行操作仍需相应授权。

每次验证冻结 HEAD、索引和完整文件字节，记录运行时与输入身份。并发变化使验证失效。租约、机器路径、原始录屏和安装回执保留本地，仓库只存脱敏结论和可重跑命令。
