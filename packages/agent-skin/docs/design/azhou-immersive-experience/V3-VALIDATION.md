# V3 全线验证合同

## 目的与证据等级

对齐 Dream Skin 与 Dragon Boot 的组合体验，保持 Azhou IP，并在宿主变化时保持原生操作可用。Dot 缺壁纸只是新暴露的覆盖缺口，不把本轮缩减为一个选择器修补。

本表是待执行合同，不是通过记录。每个场景分别记录：
- source：精确源码与机制推断，不能证明运行表现。
- synthetic：单元、DOM fixture、故障注入或自动检查，只证明其模型内行为。
- live：真实宿主上的可重复操作、视觉和功能结果。
- review：操作者对真实截图、连续录像及原型的审阅。
缺一项就保留其状态；not_run、blocked、inconclusive、invalidated 均不等于 pass。CI 全绿不是产品整体可靠的替代证据。

每份运行记录绑定源提交、构建摘要、安装身份、实际加载载荷、宿主版本/build、adapter/schema、page generation、素材摘要、输入、窗口及系统偏好。不同宿主与模式分别记账。新增、stage、rebase、载荷变化均使当前冻结结论失效。

## 跨组件不变量

1. animation ready、workspace ready、wallpaper applied和可操作互不冒充；完成、失败、取消、未知分别报告。
2. 退出不依赖最后一帧、音频结束或单个成功disposer。清理后再检查资源；旧owner不清新owner。
3. 键盘、输入值/光标/IME/选择区、滚动位置、菜单返焦及保存/取消语义保持。测试必须使用真实手势和输入，不能赋值冒充操作。
4. reduce在运行/预览/重播/降级及即时切换时都提供静态完整信息；静音不损失关键状态。
5. 图片、字体、音视频和代码分别有不可变来源/摘要/许可；生成素材也要记录身份参考与用途。
6. 先测量并冻结预算，才判断性能。原fixture的500ms退出界限不自动变成所有真实宿主SLO；保留失败样本和原始分布。
7. 只清自己仍拥有的资源。适配器故障不导致修改宿主源码、扩大权限/CSP或清理他人主题。

## 验证关闭

每一项保存期待、实际、反例、证据等级、剩余风险和恢复点。失败可否限制到单一能力要由契约与原生交互证据决定，不把全部后续工作无限阻塞，也不以“自动降级”掩盖用户要求缺失。P06仅可声明通过的宿主/页面/版本/模式，未知项继续显式列出。

### 覆盖账本关闭规则

各实现PR必须提供机器可读场景账本，字段至少包含：scenario_id、REF/REQ/AC及NH/ALIGN引用、owner阶段、宿主版本/build、页面/窗口类型、初始条件、真实动作、期待结果、期待失败方式、适用关键交叉、source/synthetic/live/review四类状态与证据引用、运行身份、失效理由、剩余风险。

每个适用REF和原18需求/12验收映射行至少关联一条正例、一条负例及适用的关键交叉记录。纯文档/来源要求的负例可采用错误归因或缺许可检验，不伪装成UI操作。无关联或缺必要live/review记录的行不可关闭。not_applicable必须有明确范围决定和版本证据。阶段完成须引用该阶段全部适用行，不以一个总PASS或抽样成功替代。
