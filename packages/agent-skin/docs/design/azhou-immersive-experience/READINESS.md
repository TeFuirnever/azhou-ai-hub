# 开发准备分阶段结论

## 结论

可以开始只读基线调查与原型准备，不可以把整个产品程序标记为ready。设计保存与审阅授权不自动授权产品开发、安装或宿主升级。本结论按poteto-mode把每个阶段拆为可验证单元，避免文档结构通过被误当成实现准备完成。

| 阶段 | 就绪结论 | 可推进范围 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| 文档归档 | 待当前修订的独立审阅与冻结校验 | 保存方案、修正依赖、提交文档PR | 精确diff审阅、校验及仓库门禁 |
| P01 基线调查 | 调查准备就绪 | 只读核对版本、安装owner、原包与现有修复差异 | 恢复原需求包或操作者明确采用替代基线；处理工作分支所有权 |
| P02 视觉原型 | 有清晰任务，正式素材未就绪 | 获准后制作不进入生产的角色与分镜原型 | 参考组合实录、时间轴/音轨/入口选择和人工审阅 |
| P10 防腐层 | 架构方向明确，生产编码尚未放行 | 在明确代码启动授权后按已核对基线实现契约子集 | P02协议冻结、共享接口与现有修复无冲突、Codex真实版本验证；DSH真实lane由P05完成 |
| P03/P04 原生与视觉集成 | 未就绪 | 不执行生产改动 | P02视觉冻结、P10边界及NH-00约束核对 |
| P05 DSH 升级适配 | 未就绪 | 只读比较官方候选和旧版能力 | 真正独立测试载荷/profile、安全回退、安装启动授权和rc.3校验 |
| P07/P08/P09 完整主题与入口 | 未就绪 | 依据覆盖矩阵继续设计 | 前序能力、格式安全和已裁决产品范围 |
| P06 发布与全面对齐声明 | 未就绪 | 无发布动作 | 全部适用REF覆盖、分端真实验收、视觉批准和必需检查 |

## 当前阻塞与解除条件

| 阻塞 | 影响 | 解除证据 |
| --- | --- | --- |
| 原18需求/12验收包尚未恢复 | NH-00、最终需求映射 | 找回原包，或操作者批准明确替代基线，不伪造编号 |
| 参考组合没有同场景真实录屏 | 全面对齐验收 | 固定版本、主题、入口、屏幕和冷热启动的参考录像 |
| 12秒与约14秒、默认音轨、入口监听范围未选 | 最终素材与启动编排 | P02原型对照及操作者选择，P09仅实现既定选择 |
| 现有修复分支另有owner与未合入变化 | 重复代码与契约冲突风险 | 只读差异清单、owner协调、已完成与剩余任务映射 |
| 多个DSH profile共用插件实体 | 升级实验可能影响日常使用 | 独立插件候选、数据边界、完整摘要及回退演练 |
| rc.3未下载或运行 | 新版兼容声明 | 官方摘要/签名验证与新旧版本真实运行结果 |
| 性能比例与首帧预算只是提案 | 性能门禁 | 先测同环境基线，在NH-10冻结数值，不凭模板判通过 |
| 在线社区生态与Windows特有效果尚未裁定 | 全功能等同声明 | 明确纳入实现或获准差异，不能暗中排除 |

## 已修正的准备问题

已补整窗主题与控件、工作面、主题库、透明度、导入应用事务、分镜、音轨和入口覆盖。已将产品选择从P09前移到P02原型审阅。P01只做调查及无时长依赖的安全约束，P02完成NH-10完整冻结。P10正式工作也依赖P02，P01后只可先做只读边界调查，避免性能协议倒置。P03依赖P02与P10。P05直接依赖P10并承担DSH新旧版本live，P10不能先称全端完成。

防腐层基于现有SkinHostContract及独立宿主适配器，不引入通用Coordinator。未知版本或失配时关闭相应皮肤能力并恢复原生操作，而不是猜选择器继续注入。DSH源码、共享实体、活跃会话与pstack保持受保护。

## 准备审核如何关闭

对精确文档提交做独立复核，检查TASKS与PLAN的依赖、所有REF的任务与验收对应、未决选择的前置位置以及本case的installed/loaded区别。运行check-plan、链接和JSON检查、禁止私有内容扫描、仓库verify与冻结前后scope比较。

文档merge-ready不等于产品ready。只有对应阶段解除条件和明确执行授权同时满足，才能开始该阶段。必要时先交付调查结论和原型，不等待所有后续阶段一次性ready，也不把未完成项勾成完成。
