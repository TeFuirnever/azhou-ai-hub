# 关于阿舟连续启动体验

## 体验目标

阿舟先出现，启动动画结束后自然进入同一视觉场景的工作区。首页保留空间和氛围，任务页让内容优先。原生控件、代码、输入框和对话内容不被皮肤代替。已有阿舟 Pet 继续独立工作。

Dream Skin 提供壁纸分层、主题和内容可读性的机制参考。Dragon Boot 提供启动编排及真实窗口交接的体验参考。两者不是待安装的新依赖，也不是可直接复制的角色或素材库。新素材仍为阿舟。

## 参考与平台边界

调查基线为 Hub `a94579b585d354f9fdbe3e04df76ae88ee019020`、Dream Skin `6fc42df` 和 Dragon Boot `c63a203`。这些引用只冻结本次阅读范围，不宣称各项目的当前远端版本。

Dream Skin 的 `runtime/dream-skin.css` 区分 full、ambient 和 banner 呈现。其 SafeCSS 与主题导入提供安全边界参考，不等于 Hub 已实现完整同款主题系统。Dragon 的 Windows 方案使用 DWM 真实窗口缩略图。其 macOS 实现按目标窗口几何与圆角衔接视频并淡出，不能据此承诺 macOS 具备相同 DWM 合成。

本期不新增 Windows 支持。macOS 先证明首帧、窗口位置、焦点与有界释放，再比较视觉连续性。若原生窗口无法可靠覆盖目标窗口，候选不能宣称无闪现。

## 原生交接是既有架构方向

[NH-DESIGN](NH-DESIGN.md)与[NH-CONTRACT](NH-CONTRACT.md)是本包采用的原生交接方案。沿用 `CodexSkinDriver`，不新建通用启动协调框架。

冷启的可信入口与单实例准入完成后，先显示原生静态阿舟底板，再启动宿主。从当前可信页面读取一次已提交设置快照。原生 WKWebView 运行共享 `animation.js`，宿主页只准备设置与壁纸，不启动第二个自动播放器。自然完成与当前代际工作区就绪分别证明后交接。热启动只激活现有宿主。

宿主 IndexedDB 仍是唯一设置权威。没有常驻同步服务时，不能同时承诺宿主启动前播放个性化内容和设置绝对最新。静态底板解决首个可见内容，设置快照解决播放一致性。不得引入第二持久偏好库来掩盖依赖。

快照读固定一条不可变记录。分块传输验证总量、顺序、长度、摘要及页面绑定，保持现有 20 MiB 合法记录上限和较小传输消息上限。快照失败不等于设置为空。原生不回写数据库。后续保存按下一次播放语义生效。

`Presentation`、`Workspace` 和 `WallpaperDisposition` 分离。页面换代废弃旧就绪证据，不重播已开始的原生动画。跳过、关闭、禁用和失败立即解除自有遮挡，不等待虚构 ready。保留 12 秒动画及已有预检 15 秒、总计 60 秒、attach 至多 45 秒的绝对预算，不能在换页或阶段切换时重置。

## 视觉如何接到现有机制

场景母版统一角色、主光、地面和镜头方向。启动末帧与工作区壁纸共享构图和焦点锚点。新动画只在已批准的 12 秒时间轴中调整节奏。素材待评审，不先改为 2.8 秒，不引入未经选择的实验。

壁纸默认保护左侧内容区，阿舟及主要道具位于右侧。首页呈现较完整的环境层，任务页降低环境对比度。按实际窗口尺寸推导 focal point 与裁切，不将某一固定屏幕的截图放大。宽窄窗口、浅深主题及多显示器均需验证。

模块边界如下。

| 文件边界 | 责任 |
| --- | --- |
| `Native/CodexSkinDriver.swift` | 启动准入、顺序与唯一协调所有者 |
| `Native/App.swift` | 原生自有窗口、PlayerStage、正式播放与 preview 隔离 |
| `Native/Wallpaper.swift` | 可信页绑定、快照传输与工作区观察 |
| `Native/SkinHostContract.swift` | 原生终态、工作区终态及消费者一致迁移 |

| `animation.js` | 共用动画内容和 12 秒编排 |
| `wallpaper/wallpaper.css` 与 `wallpaper/apply.js` | 分层、裁切、可读性及撤销 |
| `extension/codex-page-adapter.mjs` | 识别主页面，排除 Pet、mini 和 detached 页面 |
| `theme-config.json` 与 `assets/azhou/` | 审阅后的素材绑定及焦点配置 |

## DSH 独立完成

DSH 先检查实际早期 HTML hook、CSP、web 与 desktop 时序。现有 no-op host apply 与 DOM-ready client 不能证明首帧遮罩。外部插件机制也不能证明当前宿主支持。

已证明入口才能实现早期 gate、独立 watchdog 和客户端原子接管。禁止修改官方宿主来假装插件能力。能力不足时以明确阻塞记录结束 DSH 分支，Codex 可独立验收。不能把一个端通过写成双端完成。

## Pet 保持独立

已有阿舟 Pet 的选择与可见性曾获得人工确认，但不是本次新的运行观察。管理器无法观察选择不等于用户没选中。当前安装可以在旧来源回执未迁移时保持自包含可用，不应因 stale-theme 或 unknown-target 擅自卸载。

本期只比较角色一致性和皮肤页面排除边界，不自动重做 Pet。若后续确实更换 Pet，另走 prepare、生成、逐帧 QA、打包和原生安装流程，不制造回执或重用不匹配身份。具体约束见[素材规格](ASSETS.md)。
