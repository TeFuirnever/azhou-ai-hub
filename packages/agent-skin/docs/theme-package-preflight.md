# P08 read-only theme ZIP preflight subset

This developer tool does not implement the P08 theme library. P07 currently supplies only the bundled theme and workspace readability foundation. No import, installation, application, preview, settings change or last-known-good write is performed.

## Interface and ownership

Run `python3 -B packages/agent-skin/tools/theme-package-preflight.py /path/to/theme.zip`.
The tool prints one JSON object. Exit 2 means blocked, not safe to import. The report always has `structure`, `resources`, `reference_css` and `hub_mapping` layers. Each layer has `status` and stable `reasons`. `passed` applies only to that named layer. The aggregate remains `blocked` until all four can be verified. Input bytes are bound by SHA-256. Input errors do not echo private paths or archive content.

The Python interface is `preflight(path) -> dict`. The ZIP is read once with a finite ceiling into memory and never extracted. There is no output directory or host adapter parameter. This keeps the developer inspection path separate from production settings and saved-theme ownership.

Two shapes were considered. A general validator with injected decoder, CSS policy and host adapters would expose future capabilities that have no evidence yet. A narrow report-only function keeps inspection separate from import and host mapping. This subset chooses the latter. ZIP structure inspection uses the Python standard library. Image resource inspection requires Pillow with WebP support. The tested development dependency is `Pillow==12.3.0`, also pinned in the package testing contract. A missing Pillow or WebP decoder leaves resources blocked with `image_decoder_unavailable`; it never falls back to magic-only acceptance. The tool does not install dependencies.

## Accepted subset

Only flat, single-root ordinary ZIPs containing exactly `theme.json`, `theme.css` and one PNG/JPEG/WebP named by `theme.json.image` are inspected. Only the minimal theme object with exactly `schemaVersion`, `id`, `name` and `image` is supported. Schema version is 1. Studio manifests, signatures, optional theme fields, directories, wrapper roots, transport metadata, encryption, ZIP64, extra fields and unsupported ZIP methods are blocked rather than guessed. These are subset limitations, not claims that the reference rejects all such formats.

Structure checks enforce canonical ASCII file names, no duplicate or case-colliding paths, no traversal or links, no unknown entries, coherent local records, finite entry and byte budgets, bounded decompression, CRC and exact lengths. Files must be nonempty. Theme JSON rejects duplicate keys, non-finite values and unsupported fields. Resources check only nonempty UTF-8 CSS bytes. The independent `reference_css` layer checks the reference Safe CSS contract. Background extension, media magic and the actual decoder format must agree. Resources pass only after raw header dimensions satisfy 1 through 16384 pixels per side and at most 50000000 pixels, decoded dimensions match that header, and Pillow verifies and fully loads the image. Header budgets run before opening the decoder, including WebP. WebP canvas and raster dimensions must agree. Animated and multi-frame images, including APNG and animated WebP, are outside this static subset and are rejected. Truncated-image recovery is not allowed. CSS remains limited to the nonempty UTF-8 check at this layer.

## Reference and limits

The inspected reference is `Codex-Dream-Skin` commit `6fc42df48a6a5365011f55cc349e20c038e56d1d`. Its root LICENSE is MIT, copyright 2026 Codex Dream Skin Studio contributors. The ZIP and image inspection code is independently written. Safe CSS validation reuses the byte-identical `runtime/safe-css-validator.mjs` under `vendor/dream-safe-css-validator.mjs`, with the complete MIT notice alongside it. The policy JSON is a contract snapshot, not runtime configuration. The corpus suite compares it deeply with `SAFE_CSS_CONTRACT` and locks all three source hashes. See [provenance](../UPSTREAM.md#safe-css-reference-validator).

Reference `macos/scripts/extract-theme-zip-macos.sh` declares 32 MiB archive bytes, 64 MiB expanded bytes and 32 entries. `runtime/theme-package-validator.mjs` declares 1 MiB simple theme JSON, 256 KiB CSS and 10 MiB images. `runtime/image-metadata.mjs` declares 16384 pixels per side and 50000000 total pixels. No numeric compression-ratio limit was found in that extractor. This tool uses bounded actual expansion and per-file ceilings, not an invented ratio threshold.

## Deliberately blocked layers

A `resources: passed` result establishes only the static image and basic CSS byte checks above. It does not establish Safe CSS acceptance or importability. `reference_css: passed` establishes only reference parser acceptance, not rendering or Hub compatibility. The fixed Node adapter receives the already-read CSS bytes through stdin, decodes strict UTF-8 with the BOM preserved for policy rejection, and calls only `validateSafeCss`. It never calls `compileSafeCss` or `decodeAndValidateSafeCss`, whose output contains reference-host mappings. Missing Node or module, invalid UTF-8, validator rejection, exception, malformed response or runtime failure remains blocked. No CSS, source path, stack or exception message is returned. Hub mapping remains blocked because only `workspaceReadability` is currently admitted, not Dream Skin public parts. Dream Skin `minClientVersion` cannot be compared to the Hub version. A `manifest.sig` or reference `signatureIgnored` result is not publisher trust. No signature, provenance or license authorization for a user's theme is inferred.

Run the focused contract suite with `python3 -B packages/agent-skin/tools/test-production-theme-package-preflight.py` in a Python environment containing `Pillow==12.3.0` with WebP support. Tests use small encoded image fixtures and synthetic archive bytes in temporary directories. Decoder spies establish that oversized header dimensions never reach decoder open and that exact budget boundaries do reach it without allocating giant rasters. A CLI subprocess with site packages disabled verifies missing-decoder failure. The same suite checks the vendored policy, immutable hashes and exact CSS byte/rule/declaration/value limits, and runs actual child processes for failure, timeout and excessive-output cases. The optional `node packages/agent-skin/tools/dream-safe-css.test.mjs file:///path/to/reference/runtime/safe-css-validator.mjs` runs the same corpus against an independently inspected source checkout. They do not launch a real host or establish full importer security, actual rendering or complete reference-format parity.

## Remaining resource limitation

Before constructing `zipfile.ZipFile`, the reader rejects declared counts outside 1 through 32 and central directories exceeding `32 * (46 + 65535)` bytes. That byte ceiling covers at most 32 ordinary fixed headers plus maximum-length ZIP filenames; accepted entries do not permit extra fields or comments. A fixed-header scan then walks the actual variable-length records, checks every record boundary and signature, stops before record 33, and requires the actual count to match the declaration. Forging the EOCD count therefore cannot move an unbounded record list into the standard-library parser. The normal parser and local-record checks still run afterward. The 32 MiB archive ceiling remains a byte bound, not a process-memory sandbox. Image byte and pixel ceilings are not a memory or execution-time sandbox for native decoders. This subset does not establish a complete import resource-safety verdict.

## CSS process boundary

Node is a development dependency for reference CSS inspection. The Python reader retains exclusive ZIP ownership. The child receives no archive path or settings authority. Its environment is reduced to a default PATH. The response must have the exact schema, contract, status and reason fields. The parent allows at most 4096 combined stdout/stderr bytes, enforced while draining nonblocking pipes, and a 3-second I/O deadline after process creation. Timeout or excess output kills and reaps the child; stderr is never surfaced. This is not a process-creation deadline, OS sandbox, child address-space limit or complete importer resource-safety verdict. Hub mapping and aggregate status remain blocked even when image resources and reference CSS both pass. No dependency is installed automatically.
