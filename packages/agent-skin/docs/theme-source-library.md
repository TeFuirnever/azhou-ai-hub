# Isolated Dream source-package library

This developer CLI imports explicitly supplied ZIP bytes into its own local source library. It is not connected to Azhou Appearance. It does not expose an Appearance import format. The CLI does not render Dream CSS, change settings, update last-known-good, install a plugin, or contact a host.

## Commands and results

Use an existing development environment with Python, Node and Pillow with WebP support. The tested decoder environment is Python 3.14 with `Pillow==12.3.0`. The tool installs nothing. These dependencies and this CLI are not added to a user's installed host runtime.

```sh
python3 -B tools/theme-library.py --library /physical/path/to/new-library import /physical/path/to/theme.zip
python3 -B tools/theme-library.py --library /physical/path/to/new-library list
python3 -B tools/theme-library.py --library /physical/path/to/new-library read ARCHIVE_SHA256
```

`--library` is mandatory. The root must either be absent or already have this library's exact ownership/layout marker. An existing empty or otherwise unowned directory is not adopted. The parent must exist. Input and library paths reject symlink components, including macOS aliases such as `/var` when the actual path is under `/private/var`. No application-data, settings, LKG or host path is discovered automatically.

Successful import exits 0 and returns `storageStatus: imported`, `format: dream-simple-v1`, the archive SHA-256, the full validated theme object, each source file's size/digest, and whether the import was idempotent. It always returns `applyStatus: blocked` and `reason: hub_mapping_unimplemented`. The result is a storage receipt, not `safe: true`, a signature, publisher trust, a media license, or an application permit. Promo text, URLs, appearance, art and color values remain source data. URLs are not opened and source branding does not replace Azhou identity.

`read` reads the stored ZIP into one bounded buffer, verifies its digest against the requested object name, and reruns ZIP, official JSON, image and Safe CSS validation on those bytes. The Python `read_package` result also retains the original ZIP bytes. CLI read reports the validated source metadata without exporting or executing it. Missing dependencies, corruption and unknown object contents block read. It never changes the library.

List reports healthy objects as imported and individual unreadable, altered or invalid objects as blocked. A mixed list has `storageStatus: partial` and exits 2. A bad ownership marker, unknown root entry, non-digest catalog name or catalog overflow blocks the whole operation. Nothing is deleted or repaired. Other errors also exit 2 with stable reasons, not filesystem paths, CSS, exception messages or stacks.

## Accepted source contract

The byte, entry, expansion, local-record, media and CSS limits in [ZIP preflight](theme-package-preflight.md) still apply. The library accepts exactly flat `theme.json`, `theme.css` and the registered static background. It applies the pinned Dream `validateOfficialTheme` JSON contract, not the reference's more permissive local-simple fallback. Background names are exactly `background.png`, `background.jpg` or `background.webp`. `.jpeg` and arbitrary image names remain preflight-only subset behavior and are rejected by the library.

Required fields are `schemaVersion`, `id`, `name` and `image`. Optional fields are the eight Dream copy fields, `promoUrl`, `appearance`, `art` and `colors`. Validation retains Dream's code-point lengths, complete ten-color object, enums, finite art coordinates, and original color grammar. For example, the reference grammar permits three-digit RGB components without separately clamping them to 255; this library does not silently tighten that grammar and claim equivalence. Duplicate JSON keys and non-finite JSON constants are additionally rejected. Unknown fields are not dropped. All original JSON, CSS and media bytes remain inside the unchanged stored archive.

The pure validator is extracted reproducibly from fixed MIT source. It does not import Dream's filesystem staging, version/platform checks or CSS compiler. See [provenance](../UPSTREAM.md#official-theme-json-contract). Safe CSS still goes through the existing pristine parser and the bounded, sanitized Node process boundary. All checks and the eventual write use the same single input read. The input path is not reopened after validation.

## Storage transaction

The v2 ownership layout is `library-owner`, `library-lock`, `objects/<archive-sha256>/archive.zip` and `incoming/`. The canonical owner marker pins the device/inode of the fixed-content regular lock file. An earlier experimental v1 root, a missing lock, a symlink, a hard link, changed lock bytes or a replaced lock inode is rejected without automatic migration, deletion or lock recreation. Moving the owned tree on the same filesystem retains its binding; copying it does not establish a new owned lock. Original ZIPs can be explicitly reimported into a fresh root. No theme ID becomes a path, no manifest or CSS is executed, and no mutable catalog index is maintained. Same ID with different bytes produces independent objects. Reimport of the same validated bytes verifies the existing complete object and does not rewrite it. The local catalog limit is 1024 objects; it is not a Dream format limit.

Initialization prepares the complete owned root in a private sibling directory and publishes it with no-replace rename. A partial marker/directory failure cannot expose a half-initialized root or force adoption of an unknown directory. Retry uses a new private stage. Import writes and fsyncs the original archive in a private `incoming` directory, verifies the written bytes, then publishes the complete digest directory atomically. Darwin `renameatx_np(RENAME_EXCL)` and Linux `renameat2(RENAME_NOREPLACE)` refuse even a racing empty destination. Unsupported publication primitives fail closed. A racing winner must pass full read validation before the loser can report idempotency.

Directory descriptors are pinned and every path component is opened without symlink following. Root and owned-child identities are checked before and after publication. Unknown existing roots, object contents and links are never overwritten or deleted. Cleanup is limited to unchanged entries created in the current private stage; unknown or changed entries are preserved. Interrupted incoming stages are outside the visible catalog and are not read, executed or automatically reclaimed. A crash may leave such quarantined stages or an unpublished initialization sibling for manual inspection. It cannot make a partial object appear in list. A failure after atomic publication can leave a complete object even if a later durability check fails; retry verifies it rather than replacing it.

The one shared invariant is the local catalog capacity. Independent archives still have separate content-addressed objects, with no shared mutable index. Writers prepare and fsync their private files outside a library-wide `flock`. The nonblocking exclusive lock then covers the fresh capacity/membership check through atomic publication and directory fsync. A waiter checks the pinned root, owner and lock identity on every retry, uses a two-second monotonic retry budget before returning `library_busy`, and never silently creates a second lock. This retry budget is not a deadline for filesystem I/O or OS scheduling. Normal exit closes the descriptor and abrupt process exit releases the OS lock. Full image, JSON and CSS validation remains outside this critical section. An already-present identical package remains a read-only idempotent result. Two different packages competing for one remaining slot cannot both publish; the loser gets `library_size`, and the library remains readable at its limit.

These checks are not an OS sandbox or proof against arbitrary same-user mutation between observations. Native image decoding is still not an address-space or execution-time sandbox. No complete importer-resource-safety or host-rendering claim follows from storage success.

## Verification and evidence boundaries

Run `python3 -B tools/test-production-theme-package-preflight.py`, `python3 -B tools/test-production-theme-library.py` and `node --test tools/dream-theme-validator.test.mjs`. The macOS dependency-equipped repository gate and macOS CI run the Python suites. The production coverage collector discovers the new Python and JavaScript suites automatically; running these commands alone is not a 95% whole-package coverage result.

The tests construct their own small PNG and complete official-contract JSON fixture. No previously frozen, authorized external simple ZIP was available in the inspected Dream checkout. The fixture proves the contract and storage transaction, not external-theme compatibility, media permission or visual quality. Tests exercise original-byte round trip, process-restarted CLI reads, same-ID versions, concurrent idempotency, two real processes synchronized at the last-slot boundary for limits one and two, bounded lock waiting, changed lock identity, crash release, actual process interruption before publication, write failures, directory replacement, unknown destinations, symlinks, tampering, missing decoders and validators, and unchanged sentinel settings/LKG/host files. Real CSS mapping, UI import, explicit application, host capability checks, rollback and host visual acceptance are separate future work.
