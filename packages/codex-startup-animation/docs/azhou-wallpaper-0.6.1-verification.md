# 0.6.1 底部壁纸遮挡修复验收

日期：2026-10-24（北京时间）。当前安装版本：**0.6.1 / build 6**。

**结论：用户截图中的底部整条深色遮挡已修复，并在正在运行的真实 Codex 页面核实。** 使用最终安装包直接应用到同一个官方进程 PID 80172；未退出、重启或重新加载用户会话。实机验收范围为当前深色主题、1512×889 点、2× Retina。深浅色模拟回归另行记录，不与实机范围混写。

## 1. 原因与原版对照

用户要求保留原有壁纸效果并替换为阿舟素材。问题不是 PNG 损坏，也不是该图的透明通道失效，而是 0.6.0 恢复壁纸时改写了背景处理，却遗漏了真实聊天页底部的一层背景。

原版 Git HEAD 的 `extension/wallpaper.css` 通过根元素的 `--color-surface: transparent !important`、`--color-surface-secondary: transparent !important` 等变量，使使用这些表面颜色的背景透明。0.6.0 改为只清理已识别的外壳节点及工作区伪元素、保留全局官方颜色变量，但没有为聊天页底部的装饰底板补上等效规则。

实机中的遮挡节点位于 `[data-thread-scroll-footer]` 下，是类名以 `_background_` 开头的直接子节点，并带有 `bg-surface`、`pointer-events-none` 等类。它横跨内容区，背景为 `rgb(24, 24, 24)`。这块底板与真正的输入框是不同的节点。

0.6.0 的模拟页只有输入框，没有这层真实底板；其 `applied` 判定也只核查图片、外壳和工作区。因此存在“状态成功、真实画面被截断”的验收缺口。该缺口不能用已记录的窄窗口输入框遮挡限制解释。

## 2. 本次改动

- `wallpaper/wallpaper.css`：定点清除主界面内的线程 footer 及其直接装饰背景，不清除嵌套输入框的底色。
- `wallpaper/renderer.js`：新增 `footerSurfaces`、`footerBackgroundClear`；已识别底部背景不透明时，`applied` 必须为 false。
- `wallpaper/preview.html`：加入独立的 64 点高整行装饰底板，输入框置于其兄弟内容层，复现实际层级。
- `tools/test-wallpaper.mjs`：补充深浅主题下的透明背景、输入框保护、错误候选回滚、状态失效及恢复检查。
- 构建和包核验版本更新为 0.6.1 / build 6；README 与项目规则同步。

本轮未更换或重绘图片，未改变人物大小、位置、渐变或启动动画。没有恢复原版的全局颜色变量覆盖。
