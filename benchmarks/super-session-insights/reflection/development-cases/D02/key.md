# 评估键 — CASE-02

## 证据与预期结论
允许使用的事实：2026-10-01，用户希望在一节以学习为目的的微积分课中看到推导过程（SEG-02-01）；2026-11-17，用户希望为三分钟后的站会整理五条关于决策和阻塞事项的要点，并表示之后可以再展开（SEG-02-03–04）。当前简报的目标是简洁、便于快速浏览。这些记录不能证明用户对细节的长期偏好发生了改变。

不受支持的推断：“用户现在总是想要简短回答”“旧请求已经过时”，或两项偏好彼此矛盾。两项任务的目的和时间要求不同。

关键失败示例：把微积分课的完整推导要求套用到站会简报上；把一次会议的时限变成关于长期偏好的规则；忽略明确的五条要点要求。

## 七个维度的 0/1/2 锚点
- 证据保真度 — 0：声称用户要求详细的简报，或声称用户要求微积分回答只写五条（SEG-02-01、SEG-02-03）；1：注意到简洁要求，但漏掉三分钟时限或指定内容（SEG-02-03）；2：准确概括两项任务各自的要求（SEG-02-01、SEG-02-03–04）。
- 来源独立性 — 0：把两项偏好说成同一任务中的重复证据（来源关系图）；1：区分了不同会话，但漏掉任务目的差异（SEG-02-01、SEG-02-03）；2：识别为两项独立任务记录，并保留各自不同的目的（来源关系图；SEG-02-01、SEG-02-03–04）。
- 时间校准 — 0：把十月的请求当作当前要求，或声称偏好已永久切换（SEG-02-01、SEG-02-03）；1：注意到简报请求较新，但过度概括；2：以十一月的约束指导当前简报，同时承认长期偏好未知（SEG-02-03–04）。
- 解释具体性 — 0：只说“用户很忙”（SEG-02-03）；1：说“用户偏好简洁”，但不说明会议适用范围；2：把五条要点与三分钟站会联系起来，把推导细节与微积分课的学习目的联系起来（SEG-02-01、SEG-02-03–04）。
- 替代解释 — 0：断定用户的性格改变或自相矛盾（SEG-02-01、SEG-02-03）；1：笼统提到情境；2：明确考虑到学习目的和限时简报是合理的任务特定解释（SEG-02-01、SEG-02-03–04）。
- 行动价值 — 0：在这份简报中加入背景部分（SEG-02-03–04）；1：笼统说“因情境调整”，没有给出具体做法；2：现在提供五条易读的决策/阻塞事项要点，只有之后收到请求时才展开（SEG-02-03–04）。
- 负担 — 0：要求用户重复说明相同约束，或填写偏好问卷（SEG-02-03–04）；1：建议增加一次不必要的审核步骤；2：直接按用户说明的格式交付，不增加额外工作（SEG-02-03–04）。
