# Python invocation observations

This development-only `sitecustomize.py` is opt-in. A diagnostic runner may put this directory on an isolated process's `PYTHONPATH` and set `SSI_RECORDER_FIFO` to its private FIFO and `SSI_RECORDER_TARGET` to the authorized `reflection.py` path. The runner must open and continuously drain the FIFO before starting the process. Each JSON line records a Python startup, a `subprocess.Popen` attempt, or startup of the named target and a recognized operation. The observer does not record command arguments or evidence text. A target startup is not proof that the operation succeeded; inspect the tool result separately.

This is not a security monitor or a complete process trace. Python modes such as `-I`, `-S`, or `-E`, a changed environment, native launchers, inline imports, FIFO write failure, or a forged FIFO message can bypass or corrupt observations. An unmatched subprocess attempt and any unobserved path have unknown coverage, not a zero-call verdict. Do not use this recorder to assert a complete call budget or replace host-enforced filesystem and network isolation. The runner must preserve raw events and its own coverage assessment with the original tool outputs.

`run_diagnostic.py` is the bundled reference runner. Its `bind-freeze` subcommand verifies frozen material against `FREEZE.manifest.json` and copies it read-only with source and copy hash binding; its `record` subcommand creates the private FIFO (relocatable with `--fifo-path` when the observed process may not write the output directory), drains it while one authorized diagnostic command runs, preserves raw events and command output, and classifies instrumented starts, subprocess attempts, and textual exit candidates without ever counting static text as a call or proving success.
