# 输出格式规范（对标业界软件设计文档标准）

产出文档 = **Markdown 正文 + PlantUML 图**。格式对标三个业界标准，取交集作为完整性与结构判据。

## 三个对标标准

| 标准 | 取什么 |
|---|---|
| **ISO/IEC/IEEE 42010:2022**（架构描述） | 利益相关方 → 关注点 → 视图（view）→ 视点（viewpoint，记法与约定）→ 视图间对应（correspondence）；架构理由（rationale，含被拒备选）必须随文档 |
| **ISO/IEC/IEEE 1016:2009**（软件设计描述 SDD） | 设计视图的组织方式：背景/依赖识别 → 设计观（design viewpoints）逐个展开 → 设计理由；每个设计决策可追溯到需求 |
| **arc42**（免费模板，arc42.org） | 12 节实践完整清单，尤其：质量场景可验证、术语表、技术决策/风险、词汇与一致性 |

## 完整性判据（交付前逐项核对）

结构（对照所选模板剖面）：

1. 文档控制：ID、版本、状态、日期、干系人、关联文档。
2. 证据状态词表 + 「声称不得高于证据」纪律。
3. 利益相关方-关注点-视图索引（含「本文位置」与「记法」列）。
4. 词汇表：全部治理术语唯一定义点。
5. 原则与不变量（含 Seam 判据、真源/派生纪律）。
6. 分层视图 + 模块/接口表 + 数据所有权。
7. 运行流程：组件/活动图 + **时序图**（交互按时序表达的部分必须用时序图）。
8. 威胁表（STRIDE 六类闭合）+ 容量预算（门限两档）。
9. 追溯矩阵（需求 → 架构 → 下位设计）。
10. 评审门（未批准 = Draft，勾选框留空）+ 变更记录（有序、无断档）。
11. 读者指南与规范性用词约定（必须 = MUST）。
12. 全图四联注（目的/范围/版本日期/结论）且版本入变更记录。

图（PlantUML 唯一权威形式）：

- 组件图 / 活动图 / 状态图 / 时序图按表达对象选择；交互按时序表达的一律用 `sequence`。
- 时序图遵循 [sequence-guide.md](sequence-guide.md)。
- 图内术语与正文、词汇表三方一致。

## 与模板的关系

模板章节是上述判据的实体化剖面；词汇表、视图索引、追溯矩阵、读者指南与用词约定、时序图要求五项为 **skill 附加判据**——生成文档时补齐于正文，不算改模板。判据与模板冲突时以模板为准，并把差异作为偏差记录到文档「评审与变更记录」，而不是改模板（模板只读，见 [templates/PROVENANCE.md](templates/PROVENANCE.md)）。目标态标注与证据状态词 `Planned` 同义对应。
