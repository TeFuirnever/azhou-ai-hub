# 时序图业界规范（Arch Doc sequence 模式）

对标：UML 2.x sequence fragment 语义、Mermaid sequenceDiagram 社区约定、《Documenting Software Architectures》（SEI）交互视图纪律。每条都来自 ARCH-2026-001 §9 五张时序图的实测校验。

## 结构约束

- 参与者 ≤ 7；消息 ≤ 25。超限就拆：主链一张、放大图一张，放大图回指主链（「主链见 §x.y」），不重画已有内容。
- 单图单一场景。同步调用 `->` 配对虚线 `-->` 返回；**异步队列投递用实线箭头 + 消息文字标注「异步」或「至少一次」**——虚线只留给同步返回，虚线画异步投递是最常见的语义错误。
- 参与者命名沿用所在文档的既有时序图风格；命名冲突时以接口责任矩阵（canonical seam 命名）为准，并在图注补一行「参与者 ↔ Module ↔ 接缝」映射。
- 数据对象（如 RequestContext）用 note 表达，不占参与者位。

## 片段（fragment）

- 每个片段必须带条件标签：`alt 条件A / else 条件B`、`opt 条件`、`loop 每X`、`break 条件`。
- 分支覆盖三类即可交付：正常 / 降级 / 失败。失败分支的错误 Owner 标注到接口责任矩阵的错误列。
- 目标态内容（未实现的契约）在标题或参与者名显式标注（如 `(Planned)`），结论行用「目标态契约」措辞，不写成已实现能力。

## 可读性

- `autonumber` 开启，且同一文档内全部时序图风格一致（要么全有要么全无）。
- 消息文字含关键参数与枚举（逐字，如 `skip / create / none`），用 `\n` 折行保持单行可读。
- 契约性注释用 `note right of <participant>` 贴在对应生命线上；跨参与者的不变量用 `note over`。
- 自查清单：片段带标签？异步语义正确？参与者映射行？四联注（目的/范围/版本/结论）齐全且版本入变更记录？与既有图无重画重叠？
