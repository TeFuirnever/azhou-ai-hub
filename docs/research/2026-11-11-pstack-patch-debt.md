## Forward / retain / retire decision record

Each forwarded change must have an upstream issue or PR reference, a minimal **red-first reproduction** of the defect in upstream code, passing behavior with the patch, and a description of affected release/host surfaces. Forward to the owning [cursor/plugins pstack upstream](https://github.com/cursor/plugins/tree/main/pstack), not blindly to the independent mirror. The mirror may carry extra fixes, but does not replace the original upstream ownership.

A patch is retired **only after** the upstream fix is present in the chosen immutable import, a clean rebuild identifies it as redundant, the patch is removed from the series, all generated host trees are regenerated, and targeted, repository-wide, independent runtime and rollback checks pass at that exact diff. A merged external PR without a re-import is **not** a reason to delete the downstream protection.

Each maintenance batch tracks: `patch id | bug | source SHA | repro command+output | upstream issue/PR | reviewer | new source SHA | rebuild SHA | check verdict | disposition`.
