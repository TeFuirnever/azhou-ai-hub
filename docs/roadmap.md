# Roadmap

Roadmap items describe outcomes, not promises. Accepted work moves to a GitHub issue with an owner and evidence target.

## Next

- Create <code>good first issue</code> tasks that each close one reproducible failure.

## Later

- Resolve the startup-animation package's private-input/candidate handoff and native destination/state/uninstall contracts before production ownership transfer; repeat host playback and wallpaper apply/restore acceptance before retiring old sources. These are unimplemented follow-ups, not capabilities established by the source import.
- Consider shared character/export logic only when real consumers need it; a unified character system and richer Pet motion are not delivered by the current migration.
- Add more independently installable skills under the same standard.
- Generate SBOM/provenance artifacts when the project ships downloadable release artifacts, not before.
- Add a documentation site only when repository Markdown is no longer sufficient; the repository remains the authority.
