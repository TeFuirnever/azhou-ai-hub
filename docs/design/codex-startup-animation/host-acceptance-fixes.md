# 冷启动验收修订

2026-10-27，用户确认看到动画自然结束、Codex 可以点击和输入；同时报告应用内背景仍是官方背景，Command-Option-B 打开官方浏览器。用户批准质量优先继续修复。这些观察不表示 G3 或 G4 已通过。

本修订替代 RC1、FR05、T08/T26 中的 Command-Option-B 设置入口要求。播放或跳过结束后显示可点击的“阿舟外观”入口，通过 `openSettings()` 打开既有 settings-intent iframe，共用原有数据库、验证、事务与保存重播逻辑。入口在播放、加载和设置期间隐藏，结束或取消后重新显示，`dispose()` 移除入口。停止拦截冲突快捷键，不启用未经验证的新组合键。

入口使用自有固定容器和隔离样式，不定位或修改官方工具栏。它属于现有私有宿主适配，不宣称是官方插件入口。官方插件文档尚未提供当前 Codex build 的扩展界面兼容表；另建 MCP 设置服务会引入第二个持久化边界，不纳入本次修复。

窄窗口中入口不得覆盖 composer 的受保护表面。入口样式沿用动画的 CSSOM 设置方式，保留宿主 CSP；实际生成载荷须在严格 `style-src 'self'` 下验证定位、命中和打开设置。静态壁纸仍保留其独立的样式/CSP 验证，入口可用不代表壁纸已经应用。

沿用已批准的 PageController、Settings 和实际构建产物接口验收：鼠标点击入口、取消不保存、再次打开、保存一次并重播、提交值在新设置 iframe 中保留、不抢走后续用户焦点、dispose 后入口和拦截均消失。隔离浏览器证据不能替代真实宿主 G3。

壁纸仍指动画结束后保留的应用窗口背景，不包含操作系统桌面壁纸。需区分冷启动 shell 挂载、图像解码、样式接受和实际表面核查；动画 ready 不等于壁纸通过。合成延迟 shell 的复现即使修复，也不能单独证明真实宿主的根因。

保留旧固定候选及其历史证据。新字节使用独立输入和产物指纹，重新进行受影响的验收；日常安装、G4 视觉批准及对外分发仍分别处理。
