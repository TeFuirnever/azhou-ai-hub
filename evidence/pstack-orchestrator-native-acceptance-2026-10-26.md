## Fix shipped with this acceptance

The first real Kit-first run exposed a genuine gap the deterministic suites could not see (their fake runtime writes no host state): the Kit's own native validation leaves host-runtime byproducts in the home — `.sandbox_migration`, `.tmp`, `tmp`, `shell_snapshots`, `installation_id`, the `goals`/`logs`/`memories`/`queue`/`state` sqlite trio sets, and the runtime's `skills/.system` directory — and the pstack entry's unowned-target check treated them as foreign content, so the supported Kit-then-pstack order could not complete on a real machine. The check now accepts exactly that observed byproduct set, discloses the accepted entries in the plan (`host_runtime_state_accepted`), and still blocks unknown names, user-placed Skills under the home's `skills/`, and any symlink. Five new tests (`HostRuntimeStateTests` in `tests/test_integration_coexistence_install.py`) pin the acceptance, the disclosure and the three refusals. The byproduct set is the observed list of the tested client build; a client writing new names fails closed for review instead of being silently accepted.
