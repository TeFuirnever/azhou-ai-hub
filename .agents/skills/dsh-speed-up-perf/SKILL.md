# dsh-speed-up-perf

本 Skill 仅用于当前项目。用户授权、项目 AGENTS.md 和实际宿主能力优先。

## 从用户路径确定问题

先确定用户动作、可观察完成点、负载范围、资源约束、允许差异及停止条件。检查当前 base 的源码、最终合并 diff 和实际消费者；历史 PR 描述、未合并方案、估计与本次实测分开。

按任务调查冷启动、首次读/重新打开/可写恢复，长历史、大结果、工具/子会话、反复导航，首屏、分页、滚动、展开和隐藏视图激活，以及流式更新、重连、取消、结束清理。bytes、事件数、delta 数、turn/tool/child 数与 DOM 节点是不同成本维度。包含普通和尾部负载，不用大量微小同质消息冒充真实规模。

按用户延迟、CPU/分配、保留内存、发生频率与证据强度排序；每项指明生产调用者、重复工作、复杂度、最小可证伪干预与不变行为。可疑循环或大文件不是瓶颈证据。

## 测量卡与基准

沿现有 benchmark/门禁建立：用户操作、固定输入/seed 与分布、生产入口、计时起终点/排除成本、冷热、可达输出和 GC、原始样本/聚合、时间/比例/内存预算、功能验证与负对照。合成数据由常量产生；未经授权不读私有语料，授权读取也只提取不可识别聚合，不能把提示、路径、身份、ID 或密钥复制进 fixture。

- 测真实构建和实际组合，不复制算法另写 benchmark，也不为测量新增生产 export。冷/内存样本用新子进程和私有临时目录；暖样本明确保留预期缓存，setup 不偷暖冷场景。
- 前后保持输入、校验、完成点和仍可达输出一致；parse-and-discard 不能与校验且保留历史比较。不要把必需的完成工作移出计时冒充优化。
- 序列化本任务 CPU 重负载，交替/重复可比测量并保存所有样本及决定结果的聚合；不挑最快值或扩大预算掩盖回归。既有机器校准只作用于合适时间量，不缩放 bytes、counts 或比例。
- 分开组件耗时、端到端耗时、保留内存和瞬时峰值。保留内存测量时对象仍可达；约束堆运行/峰值作为另一种证据。更快但无界缓存不自动通过。
- 浏览器响应必须以真实输入及实际 UI 更新观察，包含最后一次卡顿，限制合成 producer 的速率。Node fold、fake DOM、定时 heartbeat 不证明首屏、滚动或输入延迟；排除模型/网络延迟要明说。
- CI 阈值依据实际 runner/浏览器重复校准；手动浏览器诊断先提供测量，不把 Node 校准系数套到浏览器。无实测不宣称 runner 稳定。

## 优化与验证

先保存未优化 baseline 和最小真实失败场景，用 profile、分配、工作计数或阶段耗时区分假设。一次只改一个因果因素：例如减少重复解析/复制、保持紧凑表示、流式处理中间态、延后不可见工作、缩小订阅或改善数据结构；均须复测完整消费者路径。

缓存/singleflight 明确 revision/invalidation、有界保留、独立 waiter 取消和 dispose owner。延后首次激活要测激活成本和保留状态；延后不是删除。不能跳过信任边界校验、截断历史/工具结果、削弱发布原子性、耐久性或可写就绪来提速。

运行功能/顺序/分页/错误/取消/并发/清理的 owner 测试，以及基准的端到端父场景。加入旧版或受控恢复原成本的负对照，证明阈值真能拒绝目标回归；预算须高于噪声底。

当收益在端到端消失、普通负载退化、复杂度超过收益或内存/取消/持久保证无法解释时拒绝候选。交付 `负载 → 前后绝对值/比例 → 完成点与内存语义 → 功能证据 → 负对照 → 命令/环境/限制`，历史数字、本地实测和 CI 分列。按既定场景停止，其他机会只留简短后续清单。
