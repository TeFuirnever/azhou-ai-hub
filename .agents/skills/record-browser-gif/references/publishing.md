# 发布已验证的 GIF

仅当用户明确要求把 GIF 附到 PR 时执行。先用本会话连接器/工具实际提供的附件能力；若不足，再检查已安装 CLI 的 `--help` 与版本。来源提供的 `gh --attach` 示例只适用于该实际二进制支持附件的环境，不能仅凭版本号假设可用，也不擅自安装/升级或换未经授权的外部存储。

上传前检查：

1. 用户指定的目标仓库/PR、权限、服务支持的格式/大小；本编码器默认每份最多 5 MiB，服务更严则按更严者。
2. GIF 及全部分片通过编码与视觉检查，引用的是同一次演示，原始记录和产物指纹仍对应。
3. 重新读取被演示 PR 的 live head，与记录版本一致；已变化就停止把旧图归因于新 head。工具示例来自另一 PR 时明确标出来源。
4. 正文使用精确路径的媒体引用，邻近写明 commit、树/服务、transport、真实模型是否执行、模式例外、速度/区间与分片次序。先读当前正文，保留用户其他内容；避免覆盖并发编辑。

只在已经确认支持的 CLI 中使用类似 `gh pr edit <pr> --body-file <file> --attach <gif>` 的调用；不是所有安装都提供该选项。多个分片一次发布且只引用一次。不提交 GIF 到任何分支，不修改或删除仍供历史 PR 使用的 assets 分支。

上传后复读 live head 与正文，确认 head 未变、附件引用变成可访问 URL、Markdown 确实渲染为图像，且附件返回成功和 GIF 类型。head 已变或上传结果未知时报告实际状态，先核对再重试，不能宣称验收成功。没有可用附件能力时保留本地已验证产物，明确缺口。
