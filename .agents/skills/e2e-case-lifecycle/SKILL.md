# e2e-case-lifecycle

本 Skill 仅用于当前项目。用户授权、项目 AGENTS.md 和实际宿主能力优先。

## 选择与规划

适用于界面、文件、配置/权限、远端运行等真实用户路径。先读该功能的需求、用例目录、覆盖矩阵和测试入口。开放式“这个功能应该测什么”或影响/产品语义未定的请求，先由本地 [feature-boundary-planner](../feature-boundary-planner/SKILL.md) 完成影响与状态边界规划，等 accepted cases 进入现有目录/矩阵后，再由本 Skill 接管候选实现、运行和晋级；不另起重复规划流程或直接生成巨大的状态笛卡尔积。

从 `状态 → 动作 → 条件 → 效果 → 用例` 推导候选。每项记录 accepted、undefined 或 pruned 及理由；产品语义未定义时保留问题，不把当前实现写成预期。稳定 case ID 对应初始状态、动作、逐项可观察断言、环境和版本。经过某状态但没有断言不算覆盖。

## 候选、夹具和重放

1. 新用例先进入现有候选流程，复用测试 helper；用稳定标识区分请求与完成结果。人工捕获是审查材料，不能直接当成最终测试合同。
2. 默认使用 case-local 请求/文件夹具，真正共享的基础响应才进入 common。请求区分主行为、共享辅助、忽略和合成；每个合成请求写明必要原因，不能伪装成真实提供方交互。
3. 时序按断言选择：普通功能用快速响应；停止、排队、运行中状态用受控流；节奏/性能用保留时间的记录流；错误用受控故障流。固定 sleep 不证明状态到达。
4. 夹具元数据分别表达候选物理位置和正式目标。先验证请求匹配、元数据、目标路径与断言，再执行显式指定夹具的隔离重放，证明不依赖隐式共享数据；然后检查默认运行入口。
5. 保留失败尝试、日志、截图/录像和未执行断言。前一步失败导致后续断言没跑时标为 partial/failing 或 blocked，不能把新写断言标为 covered。covered 必须链接该 case 的实际通过记录并绑定输入、代码及环境。

## 晋级与准入

- 遵循本项目该套件现有的审查、晋级和准入所有者。需要人工批准时等真实批准；没有该流程不虚构 ZCode 的 `e2e:promote` 或 Docker 命令。
- 多文件晋级先 dry-run，校验待晋级 spec、fixture、manifest 和覆盖路径一致；使用现有事务，或保留可恢复快照并在验证失败时回退本次整体改动。不能只移动 spec，留下不一致的矩阵或夹具。
- 套件有容器/隔离准入时，先证明单例在该环境通过，再加入匹配 preset 跑套件。已准入且兼容的用例批量执行；真实捕获、故障注入、时序敏感、共享状态污染和特殊网络/文件系统需求才拆开。
- 完成该用例适用的类型/代码检查和项目强制验证。运行、自动检查、人工审查、晋级、CI 准入分别报告，不互相代替；本地成功不代表所有宿主或发布成功。

录像使用当前宿主支持的真实捕获方式，并记录模式；不能把截图拼接描述成连续运行录像。缺工具或环境时完成可执行部分，明确剩余证据。
