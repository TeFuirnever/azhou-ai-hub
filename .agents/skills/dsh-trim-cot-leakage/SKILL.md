# dsh-trim-cot-leakage

本 Skill 仅用于当前项目。用户授权、项目 AGENTS.md 和实际宿主能力优先。

## 判断标准

一个只看当前仓库、看不到私有会话/未提交草稿的读者，能否找到所有引用并核实断言？不能就把仍有效的事实写成独立可核实命题，删除其讨论包装；有正式 owner 就链接它。即使出处可查，普通现状文档里的改动故事也应迁到适当历史记录，而非留作当前行为说明。

先明确用户的文件/目录/diff 范围，review/audit 保持只读，fix/trim 才修改。排除 vendor/第三方源、冻结档案与原始历史。快照/fixture 是派生行为证据，不当作散文清理目标。

## 搜索线索与反例

| 候选 | 应如何处理 |
| --- | --- |
| `(decision 7)`、audit 编号、私有 design §、阶段代号 | 替换成可解析的现行 owner，或删引用但保留事实 |
| “这个 PR / 后续分支会…” | 改为现有机制；真实未完成事项归已有任务/TODO |
| “以前 / 不再 / this cut / now” 的源码变更叙述 | 现状表述；回归理由可写“没有 X 会导致 Y” |
| “第几轮审查 / reviewer 认可 / 因此这个 cast 很安全” | 保留安全不变量/理由，不保留审查对话 |
| “先 if 然后 else…” 与显然测试解说 | 代码已表达就删除；保留非显然时序合同 |
| “大概够用 / 暂时没问题” 与未标记计划 | 核实实际界限，或具名待办，不虚构保证 |
| 正文中残留另一语言的工作笔记 | 按目标语言重写，不能改代码标识 |

不要误删：可解析 issue/TODO、决定记录/复盘中的合并 PR 证据、lint/coverage suppression 的必要理由、测量值及其依据、运行时旧连接/新连接时序、协议 `/v1`、外部 RFC § 和正式文档段落、项目口吻与 Alternatives 段。`the key used to sign` 不是历史，`this project` 不是 `this PR`。

## 执行与防过度删改

搜索只是召回工具，每个命中人工判断；使用 `rg --hidden` 时显式排除 `.git`、vendor、依赖、冻结档案与生成/录制数据，排除项放在 include 之后。自然语言模式注意大小写和完整词边界。先拿一个已知正例与近似反例校准，再信任零命中；还要无模式读范围内密集说明，不能凭 regex 宣称全覆盖。

删改前列出每条事实的主体、动作、条件、时机、义务强度、例外、归属及后果。不能把“必须等待”改成“可以继续”，把假设变已交付，或删掉真实限度/证据来源。

生成内容先改 owner 再重生成；双语做最小同步；模型/UI 可见字符串需对应行为证据，纯文案审计没有它就保留并说明。检查最终引用可解析、允许历史保留、命题完整和项目相关门禁。交付已检查范围、修正、刻意保留的反例和未决项，不删除会话记录本身。
