# dsh-find-simplifications

本 Skill 仅用于当前项目。用户授权、项目 AGENTS.md 和实际宿主能力优先。

## 范围与候选

调查请求只输出候选，不自动实施。先读当前架构、测试规则、既定保留要求与活跃决定；历史拒绝是线索，须核对它针对哪个前提。广泛调查不能找到一个 dead export 就结束，也不以删除行数或候选数为目标。

寻找能减少维护义务的方案：多余 API/字段/表示、重复权威、生命周期状态、配置路径、依赖、测试和文档。逐个追问：

- 字段是否有真实 producer、转换、支持它的 endpoint/provider 和可观察 effect？传来传去但被优先级覆盖或所有实现拒绝，不等于有功能。
- 两种状态/标识是否使消费者采取不同动作？删除区别与搬到另一个文件不同；不要通过新增 marker 修补本可删除的概念。
- 消费者能否在需要的时间直接读权威值，从而删除副本、订阅、失效事件与恢复路径？先确定观察时点，不用延迟读取改变行为。
- 更窄的公开行为是否能删除整个子系统？明确牺牲的能力和现有用户，不把行为降级包装成无损清理。
- 现有生产者/消费者扩展点、平台内建或已安装依赖能否替换手写机制？计算残留 glue、升级、测试和传递依赖的总成本；新增同步 gate 维持两套定义不等于简化。

## 证明消费者与保留义务

使用实际索引或 `rg` 追符号、属性读写、构造器、discriminant、事件/wire 字符串、配置键、manifest/exports、Loader、生成资产、bin/worker 和安装后入口。评估静态 unused-code 检查器时，还要覆盖编译器插件、转换器及其他仅构建期消费的入口，并通过实际构建证明；不能按 workspace 另存一份人工例外清单来弥补漏扫。文档、fixture 与例子是否生产消费者由真实入口决定。动态插件和仓外公开扩展即使零静态引用也可能是保留义务。

候选记录：owner、有效输入到效果路径、消失/保留的维护项、兼容/能力影响、支持证据、最强保留理由、验收方法。分别归为可达性清理、需明确取舍的行为收窄、保留义务或证据不足。

验证 copy/freeze/校验的信任与所有权边界；同进程只读借用不等于可跳过文件、配置、队列、worker/wire 输入校验。区分异步 promise、reservation、flag 的真实事实，只在等价时合并；保留同步发布/回退、首次终态仲裁、callback 隔离、取消与等待清理。丢弃中断工作或持久标记是能力变化。

替代依赖需验证实际接缝：截断、大小限制、取消、时钟、打包平台、源码/构建入口；测试本项目 glue，而非只证明库符合通用规范。删掉概念却在包装层重建同等机制不是净减少。

## 记录与交付

实质建议写清问题、方案、替代、验收、风险、消费者证据与被放弃能力，复用已有决定 owner 并检查完全/部分替代；不为凑数新建重复记录。小清理按项目现有任务/注释规范处理。

评估其他分支时对照其准确独立 diff，只吸收有证据且不重叠的部分，合并理由；不因此获得关闭别人 PR 的权限。实施时同步调用者、文档、配置、快照与生成物。报告已调查范围、候选、拒绝/延后理由及实际验证，不称为穷尽审计。
