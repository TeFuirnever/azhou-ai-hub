# 对齐、分组与图标

这是本 Skill 的按需规则；数值与组件 API 以当前页面及其主题所有者为准。

## 对齐与分组

- 先区别点击区域、可见按钮底、完整图标盒和实际轮廓；透明留白属于图标盒，增大热区不应移动它。先查容器、列、slot、gap 与覆盖样式，再作有依据的局部视觉校正。
- 命名对齐对象、参照容器及轴：同角色文本起点、图标加文字整体居中、混合字号基线、多行文本首行、标题/动作两端、重复列。不能测量时在文字边缘与按钮外框之间偷换端点。
- 同时检查轴的两端。菜单与 trigger 的文本起点须合并外 padding、border、前导图标 slot 和间距。内联 SVG 的 vertical-align 依赖字体基线，不等于视觉中心；中文、英文、等宽与换行分别看。
- 空状态在扣除标题/筛选后的内容区居中；短窗口放不下时保持滚动访问，不能靠固定上边距或裁剪假装居中。扩大点击热区后检查相邻区域不重叠。
- 按同一对象/动作/重复单元分组，不按 DOM 兄弟关系分组。内层与外层间距独立判断；没有分隔线时组间应明显大于组内，标题应靠近自己内容。
- 换行、元数据与独立动作增加复杂度时，调整外层分隔，而不是乘大每个 margin。以真实留白判断，包含行高、字形、padding 与边框；相同 CSS 数值不证明相同可见距离。

## 图标复用与新绘制

先查已有图标和变体，通过共享组件复用；颜色、尺寸和消费者布局不合适不等于需要重画。现有图形表达不了含义或用户要求新设计时，说明最接近替代与缺口，提供可编辑 SVG 及实际尺寸的同类比较。

风格跟随本项目图标体系：轮廓、端点、连接、重量、留白与复杂度保持一致；通常用继承 currentColor 的功能性轮廓，保留状态、品牌和文件图形的合法色彩/填充。不要用全局对称、统一墨水面积或填满 viewBox 代替识别判断。

检查轮廓倾斜、重心、缝隙、相切和重叠，保留方向含义。在实际控件尺寸和字重下比较，放大图只用于诊断。共享 viewBox 或描边规则变化要查紧凑菜单和大图标按钮；不因一个消费者修改共享 glyph。

模糊时依次查 CSS 尺寸/祖先变换、viewBox、绘制界限、stroke/fill、设备像素位置、颜色与透明度。整数源坐标不保证清晰；曲线/斜线保留抗锯齿，不能全局 crispEdges 或任意 non-scaling-stroke 掩盖位置问题。改变像素定位或描边时检查 DPR 1/2 等实际受影响条件。

规范化用户图稿时保留原件与可识别特征，区分画布/尺寸/颜色等技术修复与轮廓/隐喻变化；不能用现成图标替换用户指定图稿。栅格参考不照描压缩噪点，不可恢复的定义特征具名待确认。交付原图、规范化图和同类在相同条件的比较。

## 使用与验收

同一动作、值或输入提示的图标和文字共享前景色、有效透明度及状态；独立清除动作、警告和品牌保留不同语义。分别检查 computed color 与祖先 opacity。

纯图标操作保留可访问名称、键盘焦点和适当说明；复用 Tooltip/信息卡，不把所有内容塞进 title。触摸行为按实际输入能力处理，辅助动作名与可交互信息说明不能混为一谈。

普通复用查受影响控件及状态；新图形或渲染变化再查相关尺寸、重量、DPR 与主题。整套修改追踪未改图形的受影响消费者；仅当用户要求全套审查才逐个盘点。设计候选、实际接入、视觉检查和人工批准分别表达。
