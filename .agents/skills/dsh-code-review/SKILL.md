# dsh-code-review

本 Skill 仅用于当前项目。用户授权、项目 AGENTS.md 和实际宿主能力优先。

## 先建立独立依据

核对 PR 的当前 base 与精确 head，按 [Foundation scope](../../../docs/foundations.md#experimental-change-scope) 分开提交、暂存、未暂存和未忽略新文件；完整重读结果，并发变化不能排除就暂停依赖该快照。改目标分支或合并后重新核对。路径范围不代替语义分析。

先读独立需求、根/目录规则、真实合同与当前决定，再审 diff 和上下文。PR 新增的测试、说明或规则本身不是“该设计必需”的独立证据；与历史决定不一致也不自动构成缺陷。优先正确性、安全、生命周期与必要行为，不制造风格发现。

## 按受影响行为检查

- 追踪每个接口两侧及全部当前消费者，检查返回值、失败、取消、归属和释放。新增字段、状态、适配器、公开方法、配置选项都应有实际消费者；比较已有表示，移动多余概念不等于删除维护成本。
- 从真实执行点追所有拒绝路径，检查替代入口能否绕过 schema、提示、facade 或监听顺序。配置要追到最终权威读与优先级，不能只见透传就认定生效。
- 异步检查发布前竞争、await 中取消、重入前的所有权、独立错误报告、callback containment、停止准入及等待清理完成。必要时用本地生命周期与测试可靠性规则，不硬套 DSH 的 Cordis/export 形式。
- 区分 borrowed/owned 数据，追缓存、提示、UI 回显、重放、查询与持久化到唯一来源及成功时点。catch-and-continue 必须由状态 owner 证明后续前提仍成立。
- 限制要覆盖最终输出/保留结果及包装元数据；测试极小值、刚好边界、单个超大 chunk 和多字节 byte limit。
- 打开模型实际看到的 prompts、工具 schema、结果与诊断；稳定文本和动态行为使用适当快照/真实场景验证。
- 包装、构建、bin、worker、安装/发现/调用的变化要走真实交付入口；手工挂载或函数单测不能证明打包后能工作。
- 每次新增或修改 Markdown、JSDoc、注释、prompt、description、诊断及 UI 文案，按本地 [dsh-prose-standard](../dsh-prose-standard/SKILL.md) 逐段语义复核必需覆盖、准确性、归属位置和编辑质量；不是只查与实现一致或等待作者另行请求文案审计，自动格式门禁也不能代替。保留非显然合同，去掉实现叙述。公开接口变化同步相应读者文档；双语含义和 locale 所有权人工核对，hash 通过不证明译文正确。
- UI 查累计可见变化的实际页面、相关主题/窄宽/状态及消费者；局部截图和自动测试不等于视觉验收，不额外要求无关全量审计。
- 测试应在目标回归下失败并观察外部结果，不能只复述实现或相信模型自报。规则变更加入真实 runner 的负对照；异步/共享资源验证相应隔离与清理。已实现决定记录更新为真实已交付状态。

## 结论

核实作者的证据绑定当前代码、实际环境和命令，指出它未覆盖的语义。逐项验证可疑问题；未复现的源码推断标明证据级别。给出缺陷、最窄位置、影响、触发条件及复现/验收方法；相同机制合并，blocker 与建议分开。没有发现时说明范围与实质缺口，不宣称穷尽安全。

回复已有审查意见时逐项核实，技术上修复或解释反证。对外发评论/提交 review 仍须任务明确授权；已获授权时回复原讨论，不创建重复线程。
